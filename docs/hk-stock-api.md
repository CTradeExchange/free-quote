# 港股 API：港股实时行情、港股数据接口与 K 线 API 指南

港股 API 是为程序、量化系统、金融应用和数据分析工具提供香港股票市场数据的程序化接口。

通过港股 API，开发者可以在自己的应用中获取港股实时行情、股票代码、最新成交价、涨跌幅、成交量、K 线、历史行情、Tick 数据以及部分市场的盘口数据。

对于需要开发股票行情软件、量化交易工具、金融数据分析平台、股票看盘系统或投资研究工具的开发者来说，港股 API 是连接应用程序与市场数据的重要基础设施。

本文介绍港股 API 的基本概念、常见数据类型、HTTP API、WebSocket API、港股代码、K 线接口以及如何选择适合项目的港股数据 API。

---

## 1. 什么是港股 API？

港股 API 是一种通过程序接口访问香港股票市场数据的方式。

与人工打开股票软件查看行情不同，API 可以让程序自动获取市场数据，并进一步进行计算、存储、分析和展示。

典型的港股 API 可以提供：

* 港股实时行情
* 港股最新价格
* 港股涨跌幅
* 港股成交量
* 港股成交额
* 港股 K 线
* 港股历史行情
* 港股 Tick 数据
* 港股盘口数据
* 港股股票代码
* 港股交易状态

例如，一个开发者可能需要：

```text
获取 00700.HK 最新价格
        ↓
通过 API 获取实时行情
        ↓
程序进行数据处理
        ↓
显示在 Web / App / Dashboard
```

因此，港股 API 本质上是：

> **让程序能够以标准化方式访问港股市场数据的接口。**

# 2. 港股实时行情 API

港股实时行情 API 是港股 API 中最常见的应用之一。

典型实时行情数据可能包括：

| 字段             | 含义   |
| -------------- | ---- |
| symbol         | 股票代码 |
| name           | 股票名称 |
| price          | 最新价格 |
| open           | 开盘价  |
| high           | 最高价  |
| low            | 最低价  |
| prev_close     | 昨收价  |
| volume         | 成交量  |
| amount         | 成交额  |
| change         | 涨跌额  |
| change_percent | 涨跌幅  |
| timestamp      | 行情时间 |

例如：

```text
Symbol: 00700.HK
Price: ...
Change: ...
Change Percent: ...
Volume: ...
Timestamp: ...
```

实际字段名称会根据具体 API 的设计有所不同。

港股 K 线 API 用于程序化获取历史或实时 K 线数据。

一个典型请求逻辑可以表示为：

```text
股票代码
+

+
时间范围
        ↓

        ↓
OHLCV 数据
```

例如开发者可能需要：

```text

```

```text
timestamp
open
high
low
close
volume
```

然后前端可以根据这些数据绘制 K 线图。

# 6. 港股 WebSocket API

如果应用需要持续接收实时行情，WebSocket 通常比不断发送 HTTP 请求更加适合。

典型架构：

```text
客户端
   │
   │ WebSocket
   ▼
行情服务器
   │
   ├── 最新价格
   ├── Tick
   ├── 成交
   └── 行情更新
```

客户端建立连接以后，可以持续接收行情更新。

例如：

```text
Client
  ↓
WebSocket Connection
  ↓
Subscribe 00700.HK
  ↓
Receive Market Data
  ↓
Update Application
```

这类架构特别适合：

* 实时行情页面
* 股票 Dashboard
* 行情监控系统
* 量化交易系统
* 实时数据分析
* 金融数据可视化

---

# 7. HTTP API 与 WebSocket API 的区别

港股数据项目通常需要同时理解 HTTP API 和 WebSocket API。

| 特性       | HTTP API  | WebSocket API |
| -------- | --------- | ------------- |
| 请求方式     | 请求一次返回一次  | 建立连接后持续接收     |
| 实时性      | 取决于请求频率   | 更适合持续实时更新     |
| 历史数据     | 非常适合      | 通常不是主要用途      |
| 单次查询     | 非常适合      | 不适合           |
| 实时行情     | 可以        | 非常适合          |
| Tick 数据流 | 不适合高频持续获取 | 更适合           |
| 开发复杂度    | 较低        | 相对更高          |

简单来说：

> **查询数据可以优先考虑 HTTP API；持续接收实时行情可以考虑 WebSocket API。**

# 8. 港股股票代码是什么？

港股股票通常使用数字代码识别股票。

例如：

```text
00700
```

对应腾讯控股。

在不同 API、数据供应商或者交易系统中，股票代码可能采用不同格式。

例如：

```text
00700
00700.HK
HK.00700
```

因此，在接入港股 API 时，需要首先确认服务商的 Symbol 格式。

不要假设所有 API 都使用完全相同的股票代码格式。

---

# 9. 为什么港股 API 的股票代码格式很重要？

假设程序请求：

```text
00700.HK
```

但是某个 API 要求：

```text
00700
```

那么程序可能无法正确返回数据。

因此，一个完整的港股数据接入流程通常需要：

```text
用户输入股票代码
        ↓
Symbol 标准化
        ↓
API 请求
        ↓
返回行情
```

对于支持多个市场的系统，更需要建立统一的 Symbol Mapping。

例如：

```text
Market
Stock Code
Exchange
Currency
Symbol
```

统一管理不同市场的股票标识。

# 10. 港股交易时间需要注意什么？

港股市场具有明确的交易时段。

开发者在处理实时行情时，需要考虑：

* 开市
* 午间交易时段
* 收市
* 非交易时间
* 周末
* 香港公众假期
* 市场临时休市
* 半日市等特殊交易日

因此，不能简单地认为：

```text
24 × 7 = 股票实时行情
```

对于行情系统，建议根据实际数据源提供的交易状态字段判断当前市场状态。

例如：

```text
PRE_MARKET
OPEN
BREAK
CLOSED
```

具体状态定义应以数据服务商 API 文档为准。

# 11. 港股盘口 API

部分港股数据服务还会提供盘口数据。

例如：

```text
Bid 1
Bid 2
Bid 3
...

Ask 1
Ask 2
Ask 3
...
```

盘口数据可以用于：

* 买卖盘展示
* 市场深度分析
* 交易策略研究
* 实时行情系统

但是需要特别注意：

> 不同 API 服务商提供的盘口级别、数据权限和更新方式可能完全不同。

因此，在选择港股 API 时，不应该只看“是否支持盘口”，还应该确认：

* 支持多少档
* 数据更新频率
* 是否实时
* 是否需要单独授权
* 历史盘口是否可用
* WebSocket 是否支持

# 12. 港股 Tick 数据 API

Tick 数据比普通行情快照更加细粒度。

一个 Tick 数据可能包含：

```text
timestamp
symbol
price
volume
trade_type
```

连续 Tick 数据可以形成：

```text
Tick 1
Tick 2
Tick 3
Tick 4
...
```

这些数据可以用于：

* 高频行情分析
* 成交分析
* 市场微观结构研究
* 交易系统
* 数据回放
* 量化研究

如果项目只需要普通行情页面，通常不一定需要 Tick 数据。

如果项目需要更细粒度的市场数据，则应该重点考察 Tick API 和 WebSocket 能力。

# 14. 港股 API 的 Python 示例

对于开发者而言，Python 是使用金融数据 API 非常常见的语言。

一个典型 HTTP 请求逻辑如下：

```python
import requests

url = "https://example.com/api/quote"

params = {
    "symbol": "00700.HK"
}

response = requests.get(url, params=params)

data = response.json()

print(data)
```

实际 API 地址、认证方式和参数格式，需要根据具体服务商的官方 API 文档进行调整。

如果使用 WebSocket，则通常采用：

```text
建立 WebSocket
      ↓
认证
      ↓
订阅股票
      ↓
接收行情
      ↓
处理数据
```


## 15.3 是否支持 K 线？

确认是否支持：

* 分钟 K
* 日 K
* 周 K

以及具体历史范围。

如果你的系统需要逐笔行情，则应该确认：

```text

```

是否属于套餐或 API 权限。

## 15.5 是否支持盘口？

如果需要：

确认：

# 19. 港股 API 常见问题

## 什么是港股 API？

港股 API 是通过程序接口获取香港股票市场行情数据的方式，可以用于实时行情、历史数据、K 线、Tick 和其他金融数据应用。

## 有没有港股实时行情 API？

有。不同数据服务商提供的实时港股数据范围、延迟、权限和价格不同，需要根据具体项目需求选择。

## 有没有免费的港股 API？

部分服务提供免费额度或开发者测试接口，但免费 API 的股票范围、调用次数、实时性、历史数据和 WebSocket 权限可能存在限制。

## 港股 API 支持 WebSocket 吗？

部分港股行情 API 支持 WebSocket。WebSocket 更适合需要持续接收实时行情更新的应用。

## 港股 API 支持 K 线吗？

很多股票行情 API 支持 K 线数据。常见周期包括分钟、小时、日、周和月。

## 港股 API 支持 Tick 数据吗？

部分 API 提供 Tick 或逐笔成交数据。是否实时、历史 Tick 的覆盖范围以及调用权限，需要查看具体 API 文档。

## 港股 API 支持盘口数据吗？

部分数据服务支持 Bid / Ask 盘口数据，但盘口深度和实时性可能不同，需要确认具体的数据级别和权限。

## 港股 API 和 A股 API 有什么区别？

港股和 A 股属于不同市场，在股票代码、交易时间、货币、交易规则以及数据字段等方面可能存在差异。因此，多市场系统通常需要进行统一的数据模型和 Symbol Mapping 设计。

## 有没有同时支持港股、A股和美股的 API？

部分金融数据 API 支持多个股票市场。如果项目未来需要同时覆盖多个市场，可以优先考虑支持多市场数据的 API。

## 有没有同时支持股票、外汇和加密货币的 API？

部分综合金融数据 API 可以通过统一的 API 接口提供多个资产类别的数据。
