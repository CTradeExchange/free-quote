
# 股票 API：实时股票行情、历史 K 线与 WebSocket 接口指南

股票 API（Stock Market Data API）允许开发者通过 HTTP 请求或 WebSocket 连接，在应用程序中获取股票市场数据。

本文介绍股票行情 API 的常见数据类型、接入方式、应用场景，以及从开源行情示例扩展到多市场金融数据 API 的方法。

如果你正在寻找股票 API、实时股票行情 API、股票 K 线 API、Python 股票行情接口或 WebSocket 行情 API，可以从本指南开始。

## 1. 什么是股票 API？

股票 API 是连接金融市场数据与应用程序的软件接口。

开发者可以利用股票 API 构建：

- 股票行情网站
- 实时价格看板
- 股票监控程序
- 量化研究工具
- 金融数据分析平台
- 交易终端
- 股票图表与技术分析工具

具体可获取的数据类型取决于数据供应商、市场、订阅权限和接口规格。

## 2. 股票 API 通常提供哪些数据？

### 实时股票行情

实时行情接口通常用于获取最新价格和市场状态。具体字段可能包括最新成交价、开盘价、最高价、最低价、成交量和价格变化等。

### 历史股票数据

历史行情可用于回测、统计分析、历史走势研究和金融图表展示。

### K 线数据

K 线通常包含 Open、High、Low、Close，也就是 OHLC 数据，并可能包含成交量和时间字段。

### Tick 与逐笔成交数据

Tick 数据可用于更细粒度的行情分析。不同供应商对 Tick、报价更新和逐笔成交的定义可能不同，需要查看具体 API 文档。

### 买卖盘与订单簿

订单簿数据可用于展示买卖报价和市场深度。支持的档位、更新频率和数据权限取决于具体市场及服务方案。

## 3. 如何选择股票行情 API？

选择股票行情 API 时，建议检查以下因素：

| 评估维度 | 需要确认的问题 |
| --- | --- |
| 市场覆盖 | 是否支持 A 股、港股和美股？ |
| 数据类型 | 是否提供实时报价、历史数据、K 线和 Tick？ |
| 接入方式 | 是否支持 REST API 和 WebSocket？ |
| 延迟 | 如何定义和测量数据延迟？ |
| 历史数据 | 可以查询多长时间的历史行情？ |
| 频率限制 | 每秒请求数、订阅数和并发连接数是多少？ |
| 价格 | 免费额度、付费方案和超额费用是什么？ |
| 使用权限 | 数据是否允许用于商业应用和再分发？ |
| 稳定性 | 是否提供服务状态、技术支持和 SLA？ |

建议根据实际应用场景进行验证，而不是仅凭接口名称判断服务能力。

## 4. 如何使用 HTTP 股票行情 API？

HTTP API 适合按需查询数据，例如获取某只股票的最新行情或指定时间范围内的历史数据。

典型调用流程：

1. 注册并获取 API 凭证。
2. 阅读供应商的 API 文档。
3. 确认请求地址、参数和证券代码格式。
4. 发送 HTTP 请求。
5. 检查响应状态和返回字段。
6. 在应用程序中处理数据。

注意：请求地址、认证方式、参数名称和响应格式均应以所使用的数据供应商的实际文档为准。

## 5. 如何使用 WebSocket 股票行情 API？

WebSocket 适合需要持续接收行情更新的应用，例如实时行情看板、股票监控和交易终端。

常见接入流程：

1. 建立 WebSocket 连接。
2. 根据服务要求进行认证。
3. 发送订阅请求。
4. 接收并解析行情消息。
5. 处理断线重连和异常。
6. 根据时间戳及消息规则更新应用状态。

实际开发中，还应关注连接限制、订阅数量、心跳机制、消息顺序和断线后的数据恢复方式。

## 7. A 股、港股和美股 API 有什么区别？

不同股票市场可能具有不同的证券代码格式、交易时段、交易日历、行情权限、报价规则和数据覆盖范围。

接入前建议确认：

- 市场标识和证券代码规则
- 时区和时间戳格式
- 交易日与节假日
- 实时或延迟数据属性
- 复权规则及历史数据定义
- 数据授权与商业使用条件

不要假定同一套字段和代码规则可以不经转换地适用于所有市场。

## 9. 常见问题 FAQ

### 什么是实时股票行情 API？

实时股票行情 API 是用于通过程序获取股票市场最新行情的接口。实际数据延迟和更新频率取决于市场、数据源、网络条件和服务方案。

### 如何选择免费的股票 API？

建议先比较免费额度、支持市场、历史数据范围、调用频率限制、WebSocket 支持以及数据使用许可。免费额度不一定意味着可以免费用于商业产品。

### 股票 API 是否支持 WebSocket？

部分股票行情服务支持 WebSocket 实时订阅。需要查看供应商的连接地址、认证方式、订阅协议和使用限制。

### 股票 API 可以用于量化交易吗？

技术上可以用于构建量化研究、行情处理和交易系统，但必须确认数据延迟、完整性、使用授权及交易系统自身的风险控制要求。

### 如何获取股票历史 K 线？

通常需要调用历史 K 线或 OHLC 数据接口，并指定证券代码、时间周期、时间范围和其他必要参数。具体参数取决于供应商。

### 股票 API 和多资产行情 API 有什么区别？

股票 API 主要关注股票市场。多资产行情 API 可以在统一服务体系下提供股票、外汇、加密货币、商品或指数等多个市场的数据，但具体覆盖范围需要逐项确认。
